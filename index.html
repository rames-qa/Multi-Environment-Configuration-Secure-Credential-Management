2 Multi-Environment Configuration (dev, staging)

Environment switching is controlled by the TEST_ENV variable (defaulting to dev). pydantic-settings dynamically loads config/${TEST_ENV}.env and overrides values with OS/CI environment variables when present.

config/staging.env

BASE_URL=https://jsonplaceholder.typicode.com
AUTH_URL=https://jsonplaceholder.typicode.com/posts
CLIENT_ID=demo-client
CLIENT_SECRET=demo-secret
TIMEOUT=10.0
MAX_RETRIES=2

config/settings.py

import os
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):
    env: str = os.getenv("TEST_ENV", "dev")
    base_url: str
    auth_url: str = ""
    client_id: str = ""
    client_secret: str = ""
    timeout: float = 10.0
    max_retries: int = 2

    model_config = SettingsConfigDict(
        env_file=(f"config/{os.getenv('TEST_ENV', 'dev')}.env", ".env"),
        env_file_encoding="utf-8",
        extra="ignore",
    )


settings = Settings()

3 Secure Credential Management

Execution Context Where Secrets Live Protection Mechanism
Local Development (Eclipse / Git Bash) Root .env file or active shell session .env is listed in .gitignore so local credentials are never committed to Git.
GitHub Actions CI/CD Repository Settings → Secrets and variables → Actions Injected at runtime via ${{ secrets.CLIENT_ID }} and ${{ secrets.CLIENT_SECRET }} and masked in workflow logs.
Configuration Precedence OS Environment > .env > config/<env>.env Real CI secrets automatically override placeholder values in tracked environment templates.

5 API Client & Token Refresh Authentication

APIClient centralizes base URL resolution, timeouts, exponential backoff retries via tenacity, structured logging, and Allure request/response attachments. BearerTokenAuth implements HTTPX's auth_flow generator to attach Bearer tokens and automatically refresh on 401 Unauthorized.

core/auth_manager.py

from typing import Generator
import httpx


class BearerTokenAuth(httpx.Auth):
    def __init__(self, auth_url: str, client_id: str, client_secret: str):
        self.auth_url = auth_url
        self.client_id = client_id
        self.client_secret = client_secret
        self._token: str | None = None

    def _fetch_token(self) -> str:
        response = httpx.post(
            self.auth_url,
            json={"client_id": self.client_id, "client_secret": self.client_secret},
            timeout=10.0,
        )
        response.raise_for_status()
        self._token = response.json()["access_token"]
        return self._token

    def auth_flow(self, request: httpx.Request) -> Generator[httpx.Request, httpx.Response, None]:
        if not self._token:
            self._fetch_token()

        request.headers["Authorization"] = f"Bearer {self._token}"
        response = yield request

        if response.status_code == 401:
            self._fetch_token()
            request.headers["Authorization"] = f"Bearer {self._token}"
            yield request

core/http_client.py

import json
import logging
import allure
import httpx
from tenacity import retry, retry_if_exception_type, stop_after_attempt, wait_exponential
from config.settings import settings

logger = logging.getLogger("api_framework")


class APIClient:
    def __init__(self, base_url: str = settings.base_url, headers: dict | None = None):
        merged_headers = {"Accept": "application/json"}
        if headers:
            merged_headers.update(headers)
        self.client = httpx.Client(
            base_url=base_url,
            timeout=settings.timeout,
            headers=merged_headers,
        )

    @retry(
        stop=stop_after_attempt(settings.max_retries),
        wait=wait_exponential(multiplier=1, min=1, max=5),
        retry=retry_if_exception_type((httpx.TransportError, httpx.TimeoutException)),
        reraise=True,
    )
    def request(self, method: str, endpoint: str, **kwargs) -> httpx.Response:
        with allure.step(f"{method.upper()} {endpoint}"):
            logger.info("Request: %s %s", method.upper(), endpoint)
            response = self.client.request(method, endpoint, **kwargs)

            allure.attach(
                json.dumps(dict(response.request.headers), indent=2),
                name="Request Headers",
                attachment_type=allure.attachment_type.JSON,
            )
            allure.attach(
                response.text,
                name=f"Response Body ({response.status_code})",
                attachment_type=allure.attachment_type.JSON,
            )
            return response

    def get(self, endpoint: str, **kwargs) -> httpx.Response:
        return self.request("GET", endpoint, **kwargs)

    def post(self, endpoint: str, **kwargs) -> httpx.Response:
        return self.request("POST", endpoint, **kwargs)

    def close(self):
        self.client.close()

6 Pytest Test Execution & Schema Validation

Session-scoped fixtures in tests/conftest.py share a single HTTPX connection pool across tests. Responses are validated against Pydantic models in models/user_models.py before running business rule assertions.

models/user_models.py

from pydantic import BaseModel, EmailStr


class UserResponse(BaseModel):
    id: int
    name: str
    email: EmailStr
    role: str | None = None

tests/test_users.py

import allure
from models.user_models import UserResponse


@allure.feature("User Management")
@allure.story("Retrieve User Profile")
def test_get_user_schema_and_business_rules(user_client):
    response = user_client.get_user(user_id=1)

    assert response.status_code == 200, f"Expected 200, got {response.status_code}"
    user = UserResponse.model_validate(response.json())

    assert user.id == 1
    assert "@" in user.email

.github/workflows/api-tests.yml

name: API Test Automation

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]
  workflow_dispatch:

jobs:
  api-tests:
    name: Execute API Automation Tests
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Repository
        uses: actions/checkout@v5

      - name: Set Up Python
        uses: actions/setup-python@v6
        with:
          python-version: "3.12"

      - name: Install Dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt

      - name: Verify Dependencies
        run: |
          python --version
          python -m pytest --version
          pip show allure-pytest

      - name: Debug Test Collection
        run: |
          ls -la
          ls -la tests/
          python -m pytest tests --collect-only -vv

      - name: Run API Tests
        env:
          TEST_ENV: staging
          CLIENT_ID: ${{ secrets.CLIENT_ID }}
          CLIENT_SECRET: ${{ secrets.CLIENT_SECRET }}
        run: |
          python -m pytest tests -vv -s --alluredir=allure-results

      - name: Upload Allure Results
        if: always()
        uses: actions/upload-artifact@v5
        with:
          name: allure-results
          path: allure-results/
          if-no-files-found: warn
          retention-days: 14

8 Allure Test Reports & Artifact Storage

During execution, allure-pytest records feature/story metadata, HTTP step breakdowns, request headers, and response payloads into allure-results/.

  • CI Artifact Retention: GitHub Actions uploads allure-results/ with if: always() and a 14-day retention policy so reports are preserved even if a test assertion fails.
  • Local HTML Rendering: Download the allure-results zip from a completed workflow run (or use local results) and run:
allure serve allure-results

9 Troubleshooting Common Pipeline Failures

Symptom / Error Root Cause Resolution
Process completed with exit code 4 Pytest collected 0 tests or received an unrecognized CLI flag (e.g. missing allure-pytest or empty tests/). Verify tests/test_*.py files exist and install allure-pytest in the active interpreter.
No files were found with the provided path: allure-results Pytest aborted during collection/import before generating any test results. Inspect the Debug Test Collection step logs for import or fixture errors.
Pydantic ValidationError on UserResponse API payload omits optional fields like role or returns unexpected types. Keep optional fields nullable (role: str | None = None) and align model fields with the target API contract.
git push rejected (fetch first) Remote main branch contains commits created directly on GitHub. Run git pull origin main --rebase before git push -u origin main.
Windows Git Bash activation error Using Linux path (.venv/bin/activate) or PowerShell script (Activate.ps1) inside MINGW64. Use source .venv/Scripts/activate in Git Bash.
GitHub Pages Hosting: Commit this index.html to the root of main, then open Settings → Pages in your repository and set Source to Deploy from a branch → main / (root) to publish this documentation live.
